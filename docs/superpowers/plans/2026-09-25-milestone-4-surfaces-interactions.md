## Review focus

1. A choice/input/link from an old dialogue or ghost is activated after replacement or rotation: no event goes to the wrong session (Tasks 3–5).
2. A referenced surface has only elements, negative offsets, missing assets or an escaping path: render safely with consistent origin or skip the invalid component; never choose an unrelated image (Tasks 1, 2, 6).
3. Multiple animation tracks, zero waits or recursive alternative starts encounter pause/resume/switch: bounded work, no replay storm, no duplicate owner/ticker (Task 2).
4. A choice/input appears near script end, or exit/switch dialogue contains one: it stays actionable and cannot leave the lifecycle transition permanently waiting on invisible UI (Tasks 3–5).
5. Scrolling/tapping a balloon or dragging a moved character: exactly one intended action and correct unscaled collision coordinates (Tasks 5–6).

## Decisions made explicit for review

These resolve underspecified behavior for this plan; they are not claims about the old implementation. Approval of the plan approves these choices.

**Protocol interpretation.** Keep the baseline's deliberate probabilities/timing rather than copying all of SSP. The [UKADOC surface reference](https://ukagakadreamteam.github.io/ukadoc/manual/descript_shell_surfaces.html) clarifies: legacy waits use 10 ms units, modern waits use milliseconds; `alternativestart` targets animation IDs; `move` offsets the base from its original position; `base` substitutes the image and collisions; element0 replaces a numbered base. Later elements stack in numeric order, and animation frames replace their track's previous frame. The canonical [Japanese reference](https://ssp.shillest.net/ukadoc/manual/descript_shell_surfaces.html) timed out during planning; the linked project translation supplied these details.

**Approved correction, 2026-09-26.** For milestone 4, legacy `KpatternN,surface,wait,alternativestart,[a.b.c]` reads IDs from the final target field, while modern alternative records read their target field; malformed lists are ignored. `sometimes` uses a 1/2 roll and `rarely` a 1/4 roll per eligible second, superseding the equal 25% statement below. SakuraScript accepts unbracketed numeric `\bN` without showing N, preserves Japanese prose adjacent to supported tags, and routes case-sensitive `On`-prefixed choice IDs directly with trailing fields as Reference0 onward. Ordinary choice IDs continue through `OnChoiceSelect(ID)` with extra fields ignored. The interaction lifetime, token, and header validation rules still apply. This correction does not add nested choices, script execution, OnChoiceSelectEx, or general SSP parsing.

**Animation policy.** Use one track per animation ID per speaker, composed in ascending ID order. `always` loops; `runonce` runs on entry to a different logical surface, not on recomposition/rotation. Both sometimes and rarely retain the baseline's independent 25% per-second roll per eligible animation. Talk may start once per 500 ms while text actually advances, including quick/sync text, and is suppressed during explicit `i`; explicit `i` starts/restarts the requested track. An already-running automatic track is not restarted by another automatic trigger. `never` has no automatic trigger but can be targeted by `i` or an alternative start; this does not add a new automatic interval. Other unsupported intervals do not run automatically.

Normalize wait ranges to inclusive millisecond ranges and inject randomness for tests. Wait precedes drawing its frame, including the first frame; test just-before/at-boundary behavior. Reject negative, reversed or overflowing waits locally; bound normalized waits to Int.MAX_VALUE milliseconds and sample with Long arithmetic. Advance only with resumed runtime time, no background catch-up; zero waits yield at least one 50 ms tick. Limit a track to 64 control transitions per tick and reject recursive alternative-start cycles for that tick. Surface -1 resets that track to the authored base/no overlay; other negative IDs are unsupported and skipped locally; logical script surface identity remains distinct from transient animation images. `OnSurfaceChange` reflects logical script changes only while the owning session is Active, not animation frames or farewell surface changes during Closing/Switching. Hidden speakers do not animate; showing them re-enters their logical surface. Changing logical surface resets that speaker's tracks. Finished tracks retain their final visual until a reset/restart/surface change (an authored -1 clears it).

**Geometry.** Authored elements form the base in shell-pixel coordinates. Compute their union bounds, retain its origin, and account for it in drawing and hit testing. The first element supplies a base when no numbered PNG exists; element0 overrides an existing numbered PNG. Later `base` elements are treated as overlay. A `base` animation frame uses the target's authored base/collisions; `move` is an absolute offset from the unshifted base, not a cumulative delta. Ordinary overlays retain base collisions. Unsupported or missing layers are skipped without losing valid parts; missing requested surface falls back to speaker 0/10 only, otherwise show an explicit unavailable visual, never arbitrary first/second PNGs. Reject a composed canvas above 8192 pixels on either axis or 16,777,216 total pixels using Long arithmetic; these are proposed allocation bounds, not compatibility claims. Report any approved fixture exceeding them before changing the limit.

**Interaction lifetime.** Pending choices or input block automatic advancement into queued dialogue, including clock replies; the current choice script still parses through later options and its remainder. Continue delivering OnSecondChange/OnMinuteChange under the existing resumed-time rules so native timer/save behavior is preserved. While blocked, retain at most one deferred reply per clock event type, replacing its content in the same FIFO position with the newest reply (coalesce any already queued clock replies when an interaction first becomes pending); this is an explicit bounded coalescing exception to ordinary reply FIFO, not suppressed event delivery. On input resolution, release deferred replies in their retained queue order; choice selection or explicit replacement clears them with the queue. Clock responses already in flight must pass the dialogue-version guard before being enqueued. Choices are collected as the script continues, including later choices in that script; encountering the first `q` must not stop parsing the menu. Keep choices visible at script completion; a replacement script, clear of that speaker, character tap, selection, ghost switch or close invalidates their tokens. Input pauses that player's cursor and consumes no accumulated playback time while waiting. OK resumes the remainder and appends the `OnUserInput(ID,text)` reply through the normal FIFO; In Active, Cancel/Back/outside dismissal resumes without emitting an event (OnUserInputCancel is outside the approved event list). Beginning close or switch invalidates the previous normal dialogue and its draft. Newly created farewell interactions belong to the outgoing transition session and remain valid until that dialogue resolves or shutdown completes. Choice selection clears dialogue/queue before `OnChoiceSelect(ID)` per baseline. Each action is consumed once before a native request. Input/choices in outgoing switch or close dialogue remain usable until answered/cancelled; response routing retains that outgoing session, and unloading waits for its resumed dialogue. While Closing, another system Back skips the farewell script and pending actions, invalidates their tokens, and proceeds through the existing bounded OnDestroy/unload path without sending OnClose again. Back from a farewell input dialog must reach this closing action; ordinary Active input Back only cancels input. During Switching dialogue, Back enters normal close for the outgoing session; another Back can skip that close dialogue. Never force-unload an uncertain native owner. No interaction/native handle persists across process death.

**UI/link policy.** Use 48 dp minimum, nonoverlapping inline choice hit areas and wrapping labels; no text ellipsis that makes choices indistinguishable. [Android guidance](https://developer.android.com/develop/ui/compose/accessibility/api-defaults) informs touch-target sizing. Keep input draft through Activity rotation using small saved UI state keyed by the interaction token; no resubmission on restoration. Input is single-line; reject CR/LF/control characters at the event boundary rather than allowing protocol-header injection. Recognize explicit http://, https:// and mailto: text only; trim terminal sentence punctuation. Balanced-parenthesis and language-specific boundary heuristics are deferred; preserve Unicode label text without promising a general URL parser. Validate again on tap. Use Compose [LinkAnnotation](https://developer.android.com/develop/ui/compose/text/user-interactions) and a fresh outbound intent, with no arbitrary ghost extras, URI grants, file/content/intent/javascript schemes or WebView. No handler produces a readable UI error, not a crash. Link taps send no SHIORI event and do not toggle stage controls.

# Native engines implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Boot and talk with Satori, Kawari 8, and YAYA ghosts, select and switch ghosts safely, recover from failed activation, and play OnClose before exit.

**Architecture:** Keep one application-owned `GhostRuntime` and its `ShioriEngine` boundary. A process-owned native host serializes every JNI operation on one dedicated OS thread and tracks ownership independently of wrapper instances. The runtime validates candidates before switching, rejects stale results by activation identity, and falls back to the bundled Kotlin engine after an ordinary load failure.

**Tech Stack:** Kotlin, Compose, StateFlow, JUnit 4, coroutines-test, focused Android instrumentation, JNI/CMake, Gradle wrapper.

**Spec:** [Approved design](../specs/2026-09-22-blind-recreation-design.md), [product baseline](../specs/2026-09-22-nanidroid-baseline-spec.md). [Milestone-one plan](2026-09-22-walking-skeleton.md) and [evidence](../../milestone-1-evidence.md) establish the current app, not native compatibility.

## Review focus

1. A second native load returns `-1`: keep the first owner intact, mark ownership unresolved, and never call unload on its behalf (Task 2 connected test).
2. Failed cleanup (`-2`, false unload, or exception with uncertain state): quarantine native engines until process restart while bundled Kotlin dialogue still works (Tasks 2 and 4).
3. YAYA changes transport charset during a request: encode with the before value, decode the response using valid response `Charset` or the after value (Task 2).
4. Candidate descriptors are malformed or missing: reject before outgoing dialogue/unload and leave current ghost and last-run setting unchanged (Tasks 3 and 4).
5. A queued old-owner request or unload crosses a switch: the native host rejects its stale lease on the dedicated thread; a completed old reply also never publishes into the new session (Tasks 2 and 4).
6. A reply script without `\e` ends once the script is fully consumed, including pending commands (one-second end pause, then next queued script), so the queue never stalls and OnClose without `\e` still finishes (Task 4).
7. Runtime lifecycle is one explicit session state, not independent flags: milestone one needed two post-review fixes (`9cdacf9`, `e86ab1f`) for flag interactions, and switching adds more. Transitions are tested as a table, including no timer events outside Active (Task 4).

### Task 2: Native host and SHIORI transport

**Interfaces:** `suspend NativeShioriHost.load(kind: NativeKind, directory: File, libraryName: String): NativeLoadResult` returns `NativeLoadResult.Loaded(lease: NativeLease)` on success; `suspend request(lease: NativeLease, event: ShioriEvent): ShioriReply`; `suspend unload(lease: NativeLease): NativeUnloadResult`; `availability: StateFlow<NativeAvailability>`. `NativeLease` is an opaque generation token, not a JNI handle. `NativeKind` has SATORI/KAWARI/YAYA. Results distinguish success, ordinary failure, and unresolved ownership; exceptions carry a visible error. The host owns exactly one process-wide thread and one process-wide ownership state. Every request/unload checks its lease against the active generation *on that thread* immediately before JNI; stale calls fail without touching the new owner. Adapt `ShioriEngine` to a suspending request so the runtime does not block its UI dispatcher.

Assert byte encoding separately from descriptor CP932. Test `decode(bytes, fallbackCharset)` for 200 + `Value`, 204, absent/garbled status, `Key:value` and `Key: value`, invalid declared charset, and non-ASCII text.

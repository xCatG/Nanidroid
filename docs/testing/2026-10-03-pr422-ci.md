## Diagnosis and focused fix

A local 200-iteration diagnostic reproduced the same expected-1/actual-0 failure
(5.336 seconds). The test's initial `runCurrent()` could also deliver the native
load return; observing `Occupied` did not establish a pending caller return.
Cancelling an already completed load cannot exercise queued-return cancellation.
The old counter polling also lacked a publication barrier and shared one deadline.

The test now holds the fake native load until the first scheduler drain finishes,
uses a dispatcher latch to establish the return is queued on the paused caller,
and then cancels. It joins cancellation, awaits terminal StateFlow publication,
and uses a subsequent load as a native-lane barrier before asserting exactly one
cleanup. Both successful cleanup/reacquisition and failed cleanup/quarantine
remain covered. No production/native/dependency change is included.

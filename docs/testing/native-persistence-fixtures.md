## Execution contract for Task 5 and Milestone 5 Task 2

1. Use a fresh staged master per engine, record the *actual* initial GET, engine file bytes/hash (or absence), device/API/ABI and request/response bytes. For Satori, assert the `見切れ利用` menu line; for LOBO, the `Talkrate` line; for YAYA, `On_username`.
2. Send the documented change GET, then the independent readback GET. An engine status alone is insufficient; assert the specified changed value. LOBO's `OnAssignTalkRate` is an actual authored handler, not a generic SHIORI setter.
3. Exercise OnMinuteChange for LOBO and inspect `profile/dict-savedata.txt` immediately. Then use the runtime's orderly switch away/back; compare saved file content/hash and read back from the *new* engine load. Repeat with Back and a fresh app process without staging again. Separately, kill the still-running LOBO writer process only after its minute-save marker is complete, and read the same saved bytes in a new process without orderly unload. For Satori and YAYA, compare the file **after unload**, since those engines save at termination; YAYA's framework may have written an earlier file.
4. For 2elf rotation, set `見切れ利用=０` using the documented event, read it, rotate the live Activity, and read it again on the same lease. Record lease/load counts and absence of repeated boot/initialize/destroy; screenshots or a constant PID alone cannot establish lease continuity. Then separately check persisted value across unload/reload.
5. If any direct GET is not callable or does not produce the documented value, record its exact request/reply and mark that corpus ghost unverified. A **separate, explicitly synthetic** minimal dictionary may then define `OnTestSet` and `OnTestRead` for that engine, with one persisted scalar and no edits to the corpus NAR. Synthetic success proves engine plumbing only, not 2elf/LOBO/Earthquake Duo behavior.
